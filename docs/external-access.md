# External access

Use SDK 0.29.0 and a matching CLI for public origins and sign-in continuation.
Apps keep their dedicated native HTTPS listener and their existing DSM admission
policy. Connect is optional: local access and a manually configured public origin
work without it. The gateway does not create tunnels or change DSM settings.

## Package policy

```yaml
identity_gateway:
  sdk: 0.29.0
  external_access:
    connect: optional
    origin_change: none
```

`connect` is `optional` or `none`. `origin_change` is `none` or `confirm`;
Apps whose upstream configuration depends on a fixed URL should declare `confirm`
so changing the URL requires confirmation. Omitting the block means
`{connect: optional, origin_change: none}`. The CLI writes the policy as
`external` in `target/sso/gateway.json`. Pin `identity_gateway.sdk` to 0.29.0
or a compatible later version when declaring external access.

### Single-origin Apps

An App whose upstream sign-in works on one fixed URL only declares
`single_origin: true` (default `false`):

```yaml
identity_gateway:
  external_access:
    origin_change: confirm
    single_origin: true
```

Without an external origin the App keeps its local addresses unchanged. While
the resolution has an accepted external origin, the primary origin is the
App's only browser origin:

- The DSM launcher (`open.cgi`) opens the primary origin plus `launch_path`
  instead of the DSM hostname and App port. Sign-in resume keeps the host that
  started the transaction.
- The App listener answers a top-level browser navigation on a local host or
  IP (`GET`/`HEAD`, `Sec-Fetch-Mode: navigate`, `Sec-Fetch-Dest: document`)
  with `302` to the same path and query on the primary origin. Accepted public
  origins are never redirected, so one public address does not disclose
  another; with both a manual and a Connect origin, sign-in works only on the
  manual one. API, native-client, subresource, frame, WebSocket, `/_sso/` and
  `/_spl/ping` requests are not redirected.
- The settings page states that only the saved public address can sign in
  afterwards, and that a Tailscale `*.ts.net` address is reachable only from the
  tailnet unless it is shared with Funnel.

Reachability of the primary origin from each network remains a deployment
responsibility: a private tailnet URL is unreachable from devices outside the
tailnet.

A public origin is `https://<DNS hostname>`: hostname case and an explicit `:443`
are normalized. IP literals, other ports, credentials, paths (including `/`),
query strings and fragments are refused. The App origin must differ from DSM's
complete origin. Private-network URLs with the App listener's port continue to
use the existing local sign-in flow.

An `external-origin` installation setting uses these public-origin rules,
independently of the App's listener port. Existing `https-origin` settings retain
their explicit listener-port contract. `installsettings.CanonicalExternalOrigin`
returns the canonical value; `ValidateExternalOrigin(value, dsmOrigin)` also
checks separation from DSM. Installation values remain private package data.

## Inputs and resolution

The App's settings page is on the DSM origin:
`/webman/3rdparty/<package>/sso/settings.cgi`. Open DSM from the local network to
configure `manual_origin` and `dsm_origin`. The gateway has no public settings
write endpoint. `settings.cgi` is the sole writer of the private state file;
it authenticates the DSM administrator and SynoToken before displaying settings
or saving changes.

The file `<StateDir>/external.json` belongs to the App UID, has mode 0600, and
contains:

```json
{"schema":1,"revision":0,"manual_origin":"","dsm_origin":""}
```

Each settings write increments `revision`, including a change back to a previous
value. Save by writing a private temporary file, syncing it, renaming it and
syncing the parent directory. Do not edit this file concurrently from App hooks
or reset its revision during an upgrade.

Connect's read-only, mode-0644 projection is
`/var/packages/SynoPkgConnect/var/spl/external.json`, with
`target/spl/external.json` as the alternate readable location. Its schema is:

```json
{
  "schema": 1,
  "dsm": {"origin": "https://dsm.example.com"},
  "apps": {
    "ExampleApp": {
      "port": 18443,
      "rev": 42,
      "public": {"origin": "https://app.example.com"}
    }
  }
}
```

The projection is not Connect's private approval state. Connect owns `rev` and
keeps it monotonic across revocation, reapproval and restarts. A paused App may
remain in the projection; Connect's proxy separately blocks forwarding.

`EffectiveExternal(cfg, state, projection)` is the shared resolver for the
gateway, settings and Compose:

- `accept` is the nonempty manual origin followed by the matching Connect
  origin, with duplicates removed. Connect contributes only when enabled and
  its App port matches this App's listener.
- `primary` is manual, then Connect, then the configured `public_origin`.
- `dsm` is the App state's `dsm_origin`, then Connect's `dsm.origin`.
- Each accepted origin is checked again against `dsm` whenever inputs change.
- `r1.r2` is the App state's revision and this App's projection revision. These
  are integer generations, not content hashes.

`NewExternalReader(cfg).Read()` polls stat at most every five seconds and
reloads when file identity, mtime or security metadata changes. Requests on
port 443, the only port an external origin may use, call `Fresh()`, which
rechecks at once. A sign-in started right after a settings save therefore
carries the saved revision. Missing,
malformed, future-schema or unsafe files count as absent. Symlinked files,
hardlinks, unexpected ownership, incorrect modes and writable parent directories
are refused. Missing inputs cause no outbound connection, warning or DSM
notification; local response codes, redirects and cookies retain their existing
behavior. Invalid input diagnostics contain no values and are rate limited.

## Sign-in and browser boundaries

Only exact canonical accepted origins bypass the local listener's port check.
`X-Forwarded-Host`, `Forwarded` and other client-supplied forwarding headers do
not add accepted origins. Native ingress still requires mutual TLS. Cookies
remain host-only, HttpOnly and Secure under HTTPS; CSRF, transaction, browser
and OIDC checks remain mandatory.

Public sign-in goes to the configured DSM origin. If there is no DSM origin,
the App displays a localized instruction to open DSM from the local network and
configure the App's external access settings. This publicly visible page prints
no hostnames, settings values or URLs.

Cold sign-in carries `<txn>:x<n>:<r1>.<r2>` through the DSM launcher, `open.cgi`
and `authorize.cgi`. `n` is `0` or `1` and indexes `accept`; revisions are 1–19
decimal digits each. Pass the entire token unchanged and URL-encoded as
`resume`; JavaScript must not parse revisions as `Number`. Both CGI entry points
use the same parser. They recompute the current resolution and use an external
origin only if both revisions and the index match. Revoked, reordered, restored,
out-of-range or malformed extended tokens fall back to the ordinary local
sign-in path. The local `<txn>:<port>` format is also accepted.

For classless OIDC Apps, configure native login or the browser bridge and use the
matching CLI launcher and `resumeOIDC` integration. A custom launcher must carry
the full token; a transaction ID or port alone cannot resume an external sign-in.
Actual App login, encrypted-data unlock and upstream redirects remain the App's
responsibility.

`GET /_spl/ping` answers only `{"package":"<package>"}` before HTTP authority
and sign-in checks. `HEAD` has the same headers and no body; other methods return
405. This is public routing metadata for detecting a wrong destination, not
identity proof or authorization to publish an App. Responses carry
`Access-Control-Allow-Origin: *` without credentials, so the DSM menu launcher
can check from the DSM origin that an external App address answers before
opening it.

## Public-proxy requirements for App authors

Public tunnels have limits beyond the gateway. Use private networking for video,
large amounts of audio or large files. A public URL does not guarantee that all
content on the approved listener belongs to one App, or that large transfers and
long-lived connections will work.

- Send data at least every 60 seconds during a long response. Include a
  heartbeat when there is no application data; do not rely on an idle connection
  surviving the public proxy.
- Stream with `Content-Type: text/event-stream`, or set
  `Cache-Control: no-transform` and flush data, to avoid edge compression or
  buffering.
- Check upload size in the client before starting an upload and display a clear
  limit. The public provider's zone plan sets the actual maximum; the Cloudflare
  Free plan has a 100 MiB request-body limit. An edge rejection does not reach
  the App and can display a generic 413 page. The gateway's own upload limit is
  an additional limit, not a replacement for this client check.
- Non-browser WebSocket clients must send the exact App `Origin`. The gateway
  rejects protected upgrades without it; public upstream routes and explicit
  native-client passthrough retain their own authentication/origin policies.
- Configure upstream response-header timeouts for the App's expected startup
  latency. Heartbeats cannot repair a timeout before any response headers arrive.

Test release artifacts through the actual public proxy: cold and warm OIDC,
header and native App login, cancellation, reconnect, upload rejection, SSE and
WebSocket behavior, and origin changes during an in-progress sign-in. Local
handler tests do not prove provider buffering, browser launch behavior or NAS
file permissions.
